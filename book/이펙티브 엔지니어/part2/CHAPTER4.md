# 반복 속도에 투자하라

## 프로그래밍 환경을 마스터 하라
개발자로 일하는 동안 어떤 종류의 소프트웨어를 만들든지 일상적으로 사용하는 기본 도구는 대체로 그대로 유지된다.
버전 관리와 명령줄을 사용한다.
게다가 프로그래밍 기술에는 특정한 기본 기술이 필요하다.
프로그래밍 환경에서 보내는 시간이 많으므로 여기에서 더 큰 효율을 추구할수록 개발자로서의 효율도 높아진다.
</br>
### 좋아하는 텍스트 에디어와 IDE를 능숙하게 다뤄라.
이맥스(emacs), 빔(vim), 텍스트 메이트(TextMate), 서브라인(Sublime) 등 어떤 텍스트 에디터가 최고인지 갑론을박이
끝없이 어어진다. 가장 중요한것은 자신이 가장 비중 있게 사용하는 도구를 능숙하게 다루는것이다.
더 효과적으로 일하는 사람에게 코딩하는 모습을 잠시 지켜봐도 되는지 물어보고
파일 탐색, 검색, 치환, 자동 완성 등 텍스트와 파일을 조작할 때 쓰는 일상적인 작업의 효율성을 높일 방법을 파악해서 익히고 연습하라.
(검색어 "프로그래밍 환경에 관한 생산성 팁")
</br>
### 생산적이고 수준 높은 프로그래밍 언어를 적어도 하나는 배워라
스크립트 언어는 컴파일된 언어에 비해 작업을 빨리 끝내야 할 때 훨씬 효과적이다.
책에서는 **파이썬**을 추천한다. 강력한 기본 기능이 내장되어 있다.
</br>
### 유닉스나 윈도우의 셀 명령(shell command)에 익숙해져라.
파이썬이나 자바 프로그램을 작성하지 않고 기본 유닉스 도구로 데이터를 조작하고
처리하면 작업을 완료하는 시간을 몇 분에서 몇 초로 줄일 수 있다.
grep, sort, uniq 등  기본 명령어를 배워라. 모든 명령어를 서로 연결해서 쓰면 원하는 형태로 데이터를 변형할 수 있다.
(유닉스 매뉴얼 페이지에 있는 설명을 읽어 보는것을 추천)
</br>
### 마우스보다 키보드를 우선 사용하라.
숙련된 프로그래머는 파일 탐색, 애플리케이션 시작, 그리고 웹 브라우징조차 가능한 한 
마우스나 트랙패트가 아닌 키보드로 할 수 있게 연습한다.
손이 키보드와 마우스 사이에서 왔다갔다하는 시간과 횟수를 생각해보면 최적화할 여지가 상당히 많다.
</br>
### 수동 작업 흐름을 자동화하라.
셸 스크립트를 사용하든 브라우저 확장 기능을 사용하든, 자동화하는 기술을 개발하는 데는 시간이 든다.
그러나 기술을 익히는 경험이 늘어나고 실력이 발전할수록 이러한 기술을 숙달하는 데 드는 비용은 점점 줄어든다.
저자는 어떤 작업을 3~4번 정도 수행했다면 자동화할 가치가 있는지 고민한다고 한다.
</br>
### 인터렉티브 인터프리터(interactive interpreter)로 아이디어를 테스트하라.
자바, C, C++ 같은 전통적인 언어에서는 작은 표현식이라도 동작을 테스트하려면 프로그램을 컴파일해서 실행해야 했다.
파이썬, 자바스크립트 등과 같은 언어에는 표현식을 평가하고 테스트해 볼 수 있는 인터프리터가 있다. 
인터프리터를 통해 프로램이 예상대로 동작한다는 확신을 얻으면 개발 속도가 크게 향상된다.
</br>
### 변경사항과 관련 있는 단위 테스트를 빠르고 쉽게 실행할 수 있게 하라.
자신이 작성한 코드가 영향을 미치는 테스트 일부만 실행해주는 테스트 도구를 사용하라.
일반적으로 테스트 호출 시간과 실행 시간이 둘 다 빨라져야 개발할 때 테스트를 더 일상적으로
활용하게 되고, 시간도 더 절약된다.
